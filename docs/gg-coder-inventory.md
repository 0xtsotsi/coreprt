# GG-Coder `dist/core/` Inventory

Source: `@kenkaiiii/ggcoder@…/dist/core/` (121 production `.d.ts` modules across root + `compaction/` `extensions/` `auth/` `mcp/` `lsp/` `oauth/` `style-packs/` `progress/`).
Generated by static reading of `.d.ts` (and `.js` where the body was needed). Test files excluded.

Buckets:
- **PROMPT-COMMAND** — slash command body from `core/prompt-commands.js` (`PROMPT_COMMANDS` export, 7 entries)
- **HOOK** — autopilot / ideal-review / loop-breaker / regrounding mechanism (function + trigger)
- **SUBAGENT** — bundled agent prompt in `core/agents.js` (`BUNDLED_AGENTS`, 2 entries)
- **SETTINGS** — config schema in `core/settings-manager.js`
- **SKILL** — skill template in `core/skills.js`
- **STYLE-PACK** — code-style config in `style-packs/packs.js` (25 language packs)
- **EXTENSION** — extension point in `core/extensions/`
- **CORE-RUNTIME** — internal mechanism CorePrt may depend on but does not sync verbatim
- **IGNORE** — not relevant to CorePrt

## Extra-detail summaries (referenced by table below)

### `core/prompt-commands.js` — `PROMPT_COMMANDS`
7 workflow templates; each is `{ name, description, prompt }`. Bodies are large markdown prompts. The names and line numbers are:
- `expand` (line 30) — find exciting new features to add (research + report).
- `bullet-proof` (line 112) — defensive security audit (uses Auditor subagent).
- `init` (line 307) — produce `AGENTS.md` + `.gg/CLAUDE.md` project context files.
- `setup-commit` (line 388) — wire up pre-commit hooks + conventional commit message rules.
- `commit` (line 409, top-level export) — markdownlint + bash -n + secrets guard + subagent review gate + push.
- `compare` (line 452) — compare this project to similar/best-in-class projects.
- `setup-skills` (line 475) — audit and install skill bundles.

Each body is a sync target — drop verbatim into `agents/_lib/.gg/commands/<name>.md` with frontmatter.

### `core/slash-commands.js` — `createBuiltinCommands` (TUI-only)
**Not a sync target.** These are the in-TUI commands exposed to the user when running `ggcoder` interactively: `model`, `compact`, `settings`, `session`, `new`, `branch`, `branches`, `add-dir`, `remove-dir`, `rewind`, `help`, `quit`. Our RPC consumer already exposes the equivalent `compact` command (`ggcoder --rpc` accepts `compact`). The rest are TUI navigation primitives that don't translate to a headless Nostr consumer.

### `core/agents.js` — `BUNDLED_AGENTS`
Two `AgentDefinition`s (see header: {name, system prompt, tools, source}). Each is the system prompt for a subagent the desktop can spawn. The names are:
- `auditor` — defensive security analyst (data-flow trace + concrete vulnerability scenarios). Used by `/bullet-proof`.
- `skeptic` — false-positive reviewer for security findings; applies exclusion rules strictly. Counterpart to auditor in `/bullet-proof`'s two-stage flow.

Both should be dropped as `agents/_lib/.gg/agents/<name>.md` so `/bullet-proof` works in CorePrt.

### `core/skills.js` — `discoverSkills` / `parseSkillFile` / `formatSkillsForPrompt`
Skill loader reads `{cwd}/.gg/skills/*.md` frontmatter (`name`, `description`, mode).
Falls back to user-scope `~/.gg/skills/` then bundled defaults. A skill = a markdown file with YAML-ish frontmatter that the agent can decide to load. **In this ggcoder version (5.34.3), the only bundled skill is `evidence-led-ui`** (sibling directory `assets/skills/evidence-led-ui/`). Sync target: copy the skill into `agents/_lib/.gg/skills/<name>.md` verbatim.

### `core/settings-manager.js` — `Settings` / `DEFAULT_SETTINGS`
Persisted at `~/.gg/settings.json` (project override at `./.gg/settings.json`). Type-import of `Settings` for the full schema; `SettingsManager.getAll()` returns it.

### `core/ideal-review.js` — `IDEAL_REVIEW_PROMPT`
Inserted as a user-role follow-up message after every response when autopilot is on. The prompt enumerates "things the agent has done that are NOT yet proven" and asks the agent to call `ideate_solution` for each, blocking the turn until proven. Constant ~ 3 KB string. **Maps directly to a CorePrt autopilot hook** if CorePrt ships its own "post-turn, pre-stop" review.

### `core/loop-breaker.js` — `LOOP_BREAK_PROMPT`
Inserted after the agent repeats the same failed tool call N times. Acts as a single forced assistant turn: "you must explicitly choose: try-different / gather-info / ask-user / report-dead-end". ~ 2 KB.
**Maps to a CorePrt autoplan loopbreaker hook** on identical-tool-failure N-strikes.

### `core/regrounding.js` — `REGROUNDING_PROMPT`
Inserted at the start of the message list when an autopilot run has been re-attached across a compaction boundary, so the agent remembers it's in autopilot and resumes the loop rather than starting fresh. ~ 700 B.
**Maps to a CorePrt "session resume after compaction" hook** if CorePrt adds long-running autopilot-mode agents.

### `core/autopilot-cycle.js`
The outer loop. One tick per agent turn:
- Provide a guided turn skeleton (`reason about whether `ideal-review` triggers, then act or call ideal-review`)
- After response: decide `continue | reject | done` based on `ideal-review` verdict or idle-text patterns
- Re-enter the loop after each verdict (max turn cap, settings-controlled)
Highest-level knob for CorePrt autopilot parity. **Hook bucket.**

### `core/autopilot-gate.js`
Pre-completion gate:
- Ensures child subagents are resolved
- Ensures `wait_agent` results are collected
- Returns the gate message injected as a final user turn so the agent confirms closure.
**Hook bucket.**

### `core/autopilot-verdict.js`
Parses the agent's reply into a verdict (`<verdict>done</verdict>` | `<verdict>reject</verdict>` etc.) and a reason, fed back into the autopilot cycle. Pure parser/router. **Hook bucket.**

### `core/custom-commands.js` — `loadCustomCommands(cwd)`
Reads `.gg/commands/*.md` (one per file, frontmatter + body). Same shape as a skill but exposed as `/slash` commands instead of an auto-loaded skill. **CorePrt could adopt the same convention** for user-authored slash commands; the implementation is < 40 lines.

### `core/slash-commands.js` — `SlashCommandRegistry`, `createBuiltinCommands`
Built-in slash commands exposed inside `AgentSession.slashCommands`. Includes `/model`, `/compact`, `/settings`, `/help`, `/clear`, `/login`, `/mcp`, plus aliases. None of these are sync targets for CorePrt — they're the surface that orchestrates a single CLI/app run. **IGNORE**.

### `style-packs/packs.js` — `PACKS`
`Readonly<Record<LanguageId, string>>`. LanguageId is the 25-language union from `core/language-detector.d.ts`. Style packs are 30–50 line idiom guides (tooling, types, errors, modules, async, avoid). One line per pack at top level:
- typescript, javascript, python, go, rust, java, kotlin, csharp, cpp, c, ruby, php, swift, scala, elixir, haskell, ocaml, fsharp, clojure, dart, lua, zig, sql, bash, terraform
**CorePrt should write its own language packs** rather than copy these — the style opinions reflect gg-coder's defaults; CorePrt's home style should be its own.

### `core/extensions/`
Extension API is the surface for plugins. `types.d.ts` declares `Extension { name, version?, activate(ctx), deactivate? }` where `ctx` exposes: `eventBus`, `registerTool(tool)`, `registerSlashCommand(cmd)`, `cwd`, `settingsManager`. `loader.d.ts` exposes `ExtensionLoader.loadAll(extensionsDir, ctx)` and `deactivateAll()`. `plugin-bundles.d.ts` is the manifest + pack/install/remove API for `.ggplugin` artifacts.
**These three files together = CorePrt's extension API.** If CorePrt wants extensions, this is the smallest viable contract. Mapping is direct.
